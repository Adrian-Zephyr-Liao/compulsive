# Development workflow

Read the root [instructions](../AGENTS.md) and [architecture](architecture.md), then the document owning the affected behavior in [documentation ownership](AGENTS.md). [package.json](../package.json) is authoritative for engine, package manager, dependencies and scripts. This is one package, not a plugin monorepo.

## Prepare and trace

1. Confirm `git rev-parse --show-toplevel`, branch and `git status --short --branch`. Note existing work before editing. Use the requested Workspace member when one is named.
2. Install dependencies only if needed with `pnpm install --frozen-lockfile`, using the package manager declared by the project. Tests require Git. Clipboard/browser/app integrations are macOS-oriented.
3. Use CodeGraph when indexed, otherwise `rg`. Trace entrypoint → owner → callers → types/exports → tests and docs. For a defect, identify the failing condition; for a feature, define inputs, outputs, errors and acceptance.
4. Select affected docs and checks before editing. Search [Agent Notes](../.agents/notes/README.md) for the owning decision; update it or record a new one only when that policy applies.

## Implement a complete change

Use the existing owner, types, helpers and dependencies. A shared fix includes every affected caller, tests and documented behavior. Make each new behavior observable in a focused test. Safety changes include a rejection case and evidence that existing data survives rejection/failure.

CLI changes may reach argument handling, JSON/TTY output, exit codes and help. Library changes may reach exports and declaration generation. RPC changes reach schemas and browser consumers. Persistence changes reach readers, writers, existing-format fixtures and failure paths. Keep these consequences in scope without introducing unrelated cleanup.

Use temporary Git repositories and `createRepositoryManager({ dataDir, defaultRootDir })` in tests. Do not run initialization, organize, migration, deletion, real push or Codex task creation on the developer's repositories to validate code. Installed `cpl` can differ from this checkout; use the built CLI for artifact acceptance, with isolated `CPL_HOME` and synthetic paths. Initialization also writes global instructions, so a CLI smoke needs an isolated home or an injected instructions path as used by existing tests.

Vite's test environment excludes system/global Git configuration and supplies synthetic author/committer identities, preventing local hooks, signing and personal identity from leaking into temporary repositories. This changes only test-child environments, never the developer's Git configuration. Reusable Git fixtures live in `tests/helpers/workspace-fixture.ts`; setup and cleanup have bounded hooks. Keep independent Git operations in separate tests, not one cumulative lifecycle journey. Clone/reference/rebase/force-push/merge/concurrent-writer scenarios are in separate clone/branch test files, and submodule preparation is outside the migration assertion's default five-second budget. There is no global test-timeout increase. Use `pnpm run test --no-file-parallelism` for a serial complete regression when diagnosing I/O contention; a run interrupted by a long suspension is not a passing verification.

## Validation

Choose rows covering the changed behavior; a passing check need not be repeated for commit or push. There is no checked-in `.github/workflows` CI configuration or coverage threshold in this checkout. Local commands are evidence only for the worktree on which they ran.

`pnpm run check` runs documentation and architecture checks followed by Vite+ format/lint/type checks. The architecture gate's scope and limits live in [architecture](architecture.md#executed-boundaries). For focused formatting/lint use `pnpm exec vp check <changed-paths>`; type checking can still include the complete TypeScript project. Only format task-owned files in a dirty checkout.

`prepublishOnly` uses that same check entrypoint before the tests, so publishing does not bypass the documentation or architecture gates. Running checks or packing is not authorization to publish.

`check:docs` checks local Markdown links/images and heading fragments, declared `pnpm run <script>` names, and Agent Note headers/status/required sections in this guidance, docs, Notes, the listed repository Skills and user/frontend READMEs. It reads files and never executes documented commands. It supports inline Markdown links (not a general Markdown parser); keep guidance links in that form. It does not validate external URLs, architecture imports, prose correctness or translations. Its file list lives in [the script](../scripts/check-agent-docs.mjs).

Browser changes need a local browser walkthrough of affected routes, refresh/deep links, interactions, loading/error/empty states, and both locales when copy changes. `pnpm run build` followed by `node dist/bin.mjs ui --no-open` serves the built frontend; use isolated test data and stop the server afterward. The existing tests do not provide a browser runner. State which interactions were actually exercised.

## Synchronize and report

Update the owners from [documentation ownership](AGENTS.md) in the same change. Keep implemented behavior separate from a proposed decision. For a command, format, security or ownership change meeting the policy, update the [Agent Note](../.agents/notes/README.md) with rationale, rejected alternatives and remaining limitations.

Review `git diff --check`, the task diff and final status. Report: outcome and user-visible impact; files and owning docs/Note; exact checks with passed/failed/not-run status; evidence paths or test names; remaining risk and next action if blocked. Report unrelated baseline failures without silently fixing or hiding them. Never describe unrun checks or mocked/live behavior as verified.

## Three task walkthroughs

| Scenario                              | Read and trace                                                                                                                  | Change and synchronize                                                                                                                                 | Evidence and decision record                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fix a dirty-worktree deletion defect  | Root instructions → architecture → Workspace spec; trace CLI/RPC → manager → lifecycle checks and their callers.                | Fix the shared check and add a failing regression in `tests/workspaces.test.ts`; update the spec only if its claimed behavior changes.                 | Run the focused regression and affected CLI tests; prove rejection preserves the files and registry. A fix restoring the documented guarantee needs no new Note; changing deletion or recovery semantics does. |
| Add a Workspace RPC action            | Root instructions → architecture → Workspace spec → frontend instructions/README; find domain owner, RPC schema and controller. | Add domain behavior, input/result types and public export only if needed; connect RPC and hook/component, both locale messages, tests and owning docs. | Run relevant Workspace/RPC/i18n tests, check and browser build; exercise the UI. A new shared operation or safety rule needs a Note describing alternatives and verification.                                  |
| Change only contributor documentation | Root instructions → documentation ownership → affected workflow and any owning Note; verify commands against `package.json`.    | Edit the single home and inbound pointers, preserving product docs unless their behavior changed.                                                      | Run docs check and whitespace check. A typo/link fix needs no Note; a new enforced engineering policy does. No product build or live Git mutation is needed.                                                   |
