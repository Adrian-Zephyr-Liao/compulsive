# Agent Note: Optional-backup bulk discard and opt-in commit drafts

Status: implemented

## Problem

Diff-first review needs a complete discard action and a commit message generated by Codex without manually copying a prompt. Bulk cleanup must not become an unconditional reset/clean, and message generation must not reuse the existing full-access conflict-resolution chat.

## Decision

Add separate editor RPCs for bulk discard with optional stash backup and staged-only commit-message generation. Both resolve current membership and freshly validate the reviewed Git fingerprint. Fingerprints include bounded regular-file bytes and identity so binary and untracked edits invalidate a destructive request, not only text diffs and porcelain labels.

Bulk discard requires confirmation and saved buffers, rejects unsafe or incomplete snapshots and unfinished/conflicted Git states, and validates every changed path. The user explicitly requested an optional backup and then **no backup by default**. No-backup execution requires another permanent-loss confirmation, restores validated HEAD/index paths and removes only reviewed new regular files not in HEAD. Selecting backup stashes the repository's tracked/untracked changes and returns a recovery ID/command. Ignored files, commits and branches remain. Partial failures are reported without attempting a rollback over newer external changes; any verified backup is retained. A scoped stash was tested and rejected because Git saved its backup but failed to clean staged renames/deletions whose old path no longer existed in the index. Repository-wide stash is permitted only after full preflight, not as a bypass for excluded files. External agent/editor writes must be paused; CPL cannot lock external processes.

Codex receives the complete bounded staged patch only after a transfer/replacement confirmation. An ephemeral read-only CLI run in a temporary directory uses existing authentication and the CLI default model, without custom user configuration/rules or project context. Shell/apps/plugins/hooks/multi-agent gates and web search are disabled. The server rejects stale results; the frontend also retains text typed while waiting. No generation step stages, commits, pushes or creates a persistent Codex project/chat.

## Alternatives considered

- Unconditional reset/clean: rejected because it bypasses recoverability and can remove ignored or unreviewed data.
- Clearing only unstaged tracked files: insufficient for the requested complete local-change cleanup.
- Reusing the full-access conflict-resolution turn: rejected because summarizing a patch needs neither project execution nor persistent chat state.
- Loading all custom Codex integrations: rejected for this bounded text-generation workflow; users who require a custom model/provider can still write the message manually.

## Consequences

No dependency or public library API is added. Internal RPC schemas and the optional status snapshot-completeness field change. The RPC requires an explicit backup boolean so cached older clients cannot accidentally receive permanent-discard semantics. Scope/unmount invalidates pending confirmations, including the second permanent-loss confirmation. New actions use the existing editor connection. Filename exclusions are not a secret detector; explicit Codex generation transfers code to the signed-in account. Managed Codex policies, real authentication/provider availability and OS-wide isolation remain external boundaries.
